# 05: 视图配置确认态与记录查询竞态修复

**What to build:** 视图配置面板保持即时交互反馈，但筛选、排序、分组的数据条件签名只使用最后一次 H-47 保存成功的 ViewConfig。记录查询在新确认配置生效时精确切换 key，旧配置响应不能污染新 key；查询具备取消、15 秒超时、显式错误与重试能力。连续配置切换和写入最终展示与当前确认配置一致的数据。

**Blocked by:** 03: P0 网格首窗口就绪与新增记录精确基线.

**Status:** ready-for-agent

- [ ] 面板乐观草稿与已确认数据配置分离；字段显隐、列宽、冻结列、行高等展示配置不驱动 Record 查询重拉
- [ ] H-47 保存继续合并连续改动并串行提交，只有保存成功后才切换筛选/排序/分组的数据条件签名
- [ ] 连续多次配置修改时不为中间草稿发起无意义查询，最终查询使用最后一次已确认 ViewConfig
- [ ] 旧 key 查询晚到只更新旧 key，不得写入新 key；不再依赖取消整表 Record 查询后全局失效作为正确性保证
- [ ] Record 查询向 HTTP 请求传递 React Query 取消信号，并设置默认 15 秒超时；超时显示可重试错误而非无限 loading
- [ ] 新配置查询期间保留上一确认结果时显示“正在应用视图条件”或等价状态，查询成功后替换为当前配置对应数据
- [ ] 继续使用服务端游标窗口和虚拟滚动，不引入全量轮询、无限重试或一次性全量拉取
- [ ] 受控 H-47/H-48 延迟与乱序用例覆盖保存未完成、旧响应晚到、连续配置切换和查询超时，并在修复前至少一条用例稳定失败
- [ ] sf-stress 六条用例在真实部署栈保持全绿，H-46/H-47/H-48 契约不改变
