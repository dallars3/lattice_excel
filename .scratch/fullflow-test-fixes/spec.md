# 全流程 P0 冒烟阻塞缺陷修复

Status: done

## Problem Statement

P0 冒烟（49 条）当前为 39 PASS / 10 FAIL，失败集中在 8 个阻塞缺陷（issue 01~08）与 1 个 P1 契约缺口（issue 09）。从用户视角看：

- 登录后首页看不到通知入口，也看不到自己是谁，无法确认当前身份。
- 删除多维表格（Base）时确认后仍提示「服务暂不可用」，Base 留在列表里，无法清理。
- 「可填写」协作者尝试修改他人记录时收到「对象已被删除」而不是「无权限」，前端因此无法转只读提示。
- 实时协作的变更帧没有序号，断线后无法判断缺了哪些变更；外链被关闭/协作者被移除后连接仍活着。
- 凭分享链接注册的新访客进不了对应 Base；重置链接后旧链接仍能跳进 Base，撤销不生效。
- 导入 Excel/CSV 全部行失败，导出始终报参数错误，导入还留下一个空壳 Base。
- 新建数据表时服务端不给默认主字段与视图，只有当前前端会补，其它调用方拿到空表。

## Solution

按「先修服务端契约、再修前端落点」推进：

1. 首页补齐身份区与通知铃铛（未读数取 H-74，完整通知中心仍属 M4）。
2. 删除 Base 时接线记录与评论清理适配器，保证删除成功且级联不可达。
3. 行级范围「仅自己」下编辑他人记录统一返回 3001，数据不变。
4. 事件总线在发布时用 outbox 行的持久序号填充 `seq`，实时帧与快照稳定携带单调序号。
5. 会话吊销帧发出后关闭目标连接（链接关闭只影响该 Base 的链接会话，权限变更只影响被移除用户）。
6. 分享链接注册后落到该 Base；网关与结构域放行链接上下文的外部账号读取 Base 结构；H-95 落点与前端路由对齐。
7. 重置/关闭链接时同步清除网关的 token→Base 缓存，旧链立即失效并进入失效页。
8. worker 调 core 的导入/导出链路补齐行级范围元数据；失败导入不留下可访问的半成品 Base。
9. 新建数据表在服务端事务内创建默认主字段与默认视图，前端兜底保留为幂等防御。

## User Stories

3. 作为登录用户，我想在首页看到自己的显示名/用户名，以便确认当前登录身份。
4. 作为登录用户，我想从用户信息处退出登录，以便统一身份入口。
5. 作为 Base 可管理者，我想删除含数据表的 Base 时真正删除成功，以便清理不再使用的表格。
6. 作为 Base 可管理者，我想在删除 Base 时看到不可恢复的强提示，以免误删。
7. 作为 Base 可管理者，我想删除后该 Base 从首页消失且任何接口都不可再访问，以便确认删除彻底。

21. 作为持分享链接的新访客，我想以「可填写」或「可查看」角色看到该 Base 的数据表，以便立即开始协作。
22. 作为持分享链接的访客，我想链接失效时看到明确的失效页，以便知道需要重新获取链接。

24. 作为 Base 可管理者，我想关闭链接后旧链接立即失效，以便紧急止损。

## Implementation Decisions

### 1. 首页身份区与通知入口（issue 01）

- 首页顶栏拆成左右两区：左侧标题与搜索/新建入口不变；右侧新增「通知铃铛 + 用户信息」。
- 通知铃铛的未读数来自 H-74；登录后拉取一次，并在页面可见时每 30 秒刷新。点击铃铛打开轻量浮层，展示未读数与「通知中心将在后续版本提供」，不实现通知列表。
- 用户信息展示显示名，缺失时回退用户名；原「退出登录」按钮移入用户信息菜单，登出行为与现有逻辑一致。
- 不新增后端接口；通知中心列表、已读操作与消息聚合仍属 M4。

### 2. 删除 Base 的清理适配器（issue 02）

- 工作台（workspace）域在组合根必须拿到两个清理适配器：记录清理（按 Base + 表清单删除记录及其历史/操作日志/计算物化行）与评论清理（按 Base 删除评论）。
- 清理顺序保持：记录 → 评论 → 分享链接 → 结构 → Base 行；任一步失败返回明确错误，不提交 Base 删除。
- 清理适配器必须幂等：重复删除不报错；无数据表时跳过记录清理。
- 只有基础设施不可用才返回 9001；业务成功返回空信封。
- 删除完成后，对该 Base 的数据表/记录/视图查询返回「对象已删除」，首页聚合不再包含该 Base。

### 3. 行级范围越权错误码（issue 03）

- 记录域在「仅自己」行级范围下，若记录存在但创建者不是当前用户：更新单元格、批量更新、删除记录、撤销删除、回滚、读历史统一返回 3001。
- 记录本身不存在或已删除仍返回 4002。
- 该决定接受「可填写用户可感知记录是否存在」的信息披露，以换取与 AC-PERM-03 及前端错误映射一致；在 ADR 中记录该权衡。

### 4. 事件序号（issue 04）

- 事件总线发布时，若事件头部的 `seq` 为 0，则使用 outbox 行的持久自增序号填充；已有非零 `seq` 保持不变。
- 该序号是 Base 内单调递增的持久序号，与增量回放使用的有效序号完全一致。
- 实时帧序列化显式输出 `seq`（含 0）与空列表字段，确保快照、单元格变更、结构变更、删除记录的帧形状稳定。
- Hub 维护的 Base 序号取已广播事件序号与客户端最后序号的最大值；join 快照返回该值。
- 增量回放按同一序号去重，保证无缺口、无重复。

### 5. 会话吊销后的连接关闭（issue 05）

- 新增「发送后关闭」语义：目标连接先把 `session_revoked` 帧刷出，再关闭连接并退出房间。
- `link_closed`：只关闭持有该 Base 链接上下文的连接；内部成员与其它 Base 的连接不受影响。
- `perm_changed`：关闭被移除用户的全部在线连接。
- 关闭必须幂等；重复吊销事件不报错、不重复关闭。

### 6. 分享链接访问与落点（issue 06）

- 网关的访问判定缓存键必须包含链接 token 与链接角色，避免外部链接会话与普通会话共用缓存；无链接上下文时保持现有键。
- 结构域的所有只读接口（数据表/字段/视图/视图配置/记录查询）对「无企业归属的外部账号」不再要求企业成员角色：租户边界改为「数据表所属 Base 的企业」，Base 级授权由网关 CheckAccess 完成。该租户解析与记录域现有外部协作者处理保持同一口径。
- 结构域的写接口仍要求企业成员或可管理角色，不放宽。
- 分享链接注册成功后，前端导航到 `/s/{token}`，由网关按已登录分支解析链接上下文并 302 到 Base；网关 H-95 的已登录落点改为前端规范路由 `/base/{base_id}`（当前为 `/bases/{base_id}`），并同步接口文档与契约测试。
- 新增前端 `/err` 路由，展示链接失效页（`kind=share-link-unavailable`），不再回退首页。
- 链接注册用户重新登录后必须仍能凭账号的链接上下文访问该 Base（链接未失效时）。

### 7. 链接重置/关闭的缓存失效（issue 07）

- 网关的分享链接缓存增加按 token 删除能力。
- 重置链接时：先读取当前链接配置拿到旧 token，调用重置成功后删除旧 token 的缓存键；关闭链接同理。
- 强制关闭「任何人」链接时：`link.closed` 事件载荷包含被关闭的 token，网关侧订阅该事件并删除对应缓存键；实时通道继续按 Base 推送吊销帧。
- 缓存删除失败只告警不阻断主流程；`/s/{token}` 在缓存未命中时回源 core 校验，旧 token 必须落到失效页。
- 会话级权限缓存仍允许最长 55 秒生效窗口，符合 AC 的「1 分钟内失效」。

### 8. 导入导出的行级范围元数据（issue 08）

- worker 调 core 的记录读写必须携带行级范围元数据：导入使用「全部」范围，导出使用「全部」范围；同时保留企业、Base、数据表元数据。
- 网关在导入/导出入口把调用方裁决结果（内部身份、Base、动作）传给 worker，worker 不得自行推断权限。
- 导入在全行失败或任务失败时，不得留下可访问的半成品 Base：要么删除该 Base，要么保持「导入中」隔离态并在失败后清理；成功完成才解除隔离。
- 导出必须按当前视图配置（筛选、排序、隐藏字段）取数，文件名为 `Base_表_视图_YYYYMMDD.{xlsx|csv}`，公式/引用输出计算值。
- 外部协作者导出仍由网关在 API 层拦截 3002。

### 9. 新建数据表默认结构（issue 09）

- 结构域的新建数据表在同一个事务内创建：数据表行、默认主字段「标题」（多行文本）、默认视图「表格」（表格视图）。
- 返回的数据表摘要中字段数与视图数均为 1；后续列表查询与计数一致。
- 前端现有的默认结构兜底保留，但改为幂等防御：检测到已有字段/视图时不重复创建。
- 该变更不回溯修复历史空表；如需修复由运维脚本单独处理。

### 10. 契约与文档同步

- H-95 已登录落点由 `/bases/{id}` 调整为 `/base/{id}`，需同步接口文档、前端路由与契约测试。
- W-08/W-09/W-10/W-11 的 `seq` 与 `session_revoked` 关闭语义写入接口文档的 WS 章节。
- 行级范围越权返回 3001 写入记录域接口备注与 AC-PERM-03 的验收口径。
- 为「链接上下文的外部账号租户边界」与「行级越权 3001 的信息披露权衡」各补一篇 ADR。

## Testing Decisions

- 好的测试只断言外部行为：HTTP 信封与状态码、WS 帧序列与连接状态、通过 API 读回的数据与最终可见性；不直接断言私有函数或数据库内部实现细节。基础设施（Redis、MySQL、gRPC）只在包级测试里用现有 fake/harness。
- **主验收缝（黑盒）**：部署后的 HTTP/WS 边界。直接复用本轮已建立的 API/WS 执行器与 Playwright 套件，按 TC 编号验收；修复完成后 49 条 P0 必须全绿。
- **辅助缝（包级）**，全部使用既有 harness：
  - 网关管线：链接入口三分支、缓存失效、链接注册落点、H-95 路由对齐。
  - 分享域：链接角色裁决、重置后旧 token 不可解析、关闭/强制关闭事件载荷含 token。
  - 结构域：外部无企业账号的只读租户解析、新建表默认结构事务、默认结构幂等。
  - 工作台域：删除 Base 的记录/评论清理适配器与幂等、失败不提交。
  - 记录域：行级「仅自己」越权 3001、不存在 4002、数据不变。
  - 事件总线：outbox 发布填充序号、同序号回放去重、快照序号取最大值。
  - 实时通道：吊销帧发送后关闭连接、link_closed 只影响目标 Base、perm_changed 只影响目标用户。
  - 导入导出域：worker 转发元数据含行级范围、导入失败清理、导出视图范围与命名。
- 既有先例：网关 pipeline fake、分享域 governance/identity 测试、记录域 collaborator_write 测试、worker importexport 测试、实时通道 hub_revocation/hub_broadcast 测试。
- 测试数据：沿用本轮夹具（正常 CSV/XLSX、脏数据、1 万/5 万行按需）；外部账号使用链接注册与无企业账号两条路径。
- 限速：注册 10/min、登录 20/min，自动化用例需内置 5003 重试与等待滑窗。

## Out of Scope

- M4/M5 的完整通知中心列表、分享弹窗、导入导出向导、评论界面、冲突三动作弹窗、离线横幅、移动端专属 UI。
- P1/P2 用例与性能预算（首屏 3s、5 万行滚动、兼容矩阵）。
- 历史遗留空表的批量修复。
- Redis/MySQL 高可用、多实例 WS 粘性会话、事件总线架构重写。
- 通知的已读/清理交互（仅保留未读数入口）。

## Further Notes

- 缺陷来源：`.scratch/fullflow-test/issues/01~09`；执行证据：`.scratch/fullflow-test/p0-results.md` 与 `.scratch/fullflow-test/p0-api-results.json`。
- 本轮已确认的系统性根因有三类：清理/权限等组合根 seam 未接线；worker/结构域对外部账号的租户假设；事件序号与链接缓存缺少失效机制。修复时优先收敛这三类，而不是逐用例打补丁。
- 已确认的契约变更只有 H-95 落点与行级越权错误码两处；其余为缺陷修复，不改变既有通过用例的行为。
- 建议修复顺序：事件序号与会话吊销（实时通道）→ 删除 Base 与新建表默认结构（数据完整性）→ 分享链接访问与缓存失效（外部入口）→ 导入导出元数据 → 首页身份区与越权错误码（体验与契约）。
- 回归门槛：`p0-api.mjs` 全 PASS、`web/e2e/p0.spec.ts` 全 PASS、`contract-test.ps1` 与 `check-docs.ps1` 退出码 0。
