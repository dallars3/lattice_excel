# 验收期缺陷整改（N7 注册建企 · N5 公式回填 · N2 人员目录 · 前置：测试库隔离护栏）

Status: ready-for-agent

## Problem Statement

web-m2-fixes 整改验收期发现三个存量产品缺陷（根因均已定位到代码级，非本轮回归）：

1. **N7（P1）注册不建企业**：注册页承诺「注册即为你新建一个企业，你将自动成为该企业所有者」，且企业名称标注可选；但后端注册在「企业名称与链接令牌均为空」的默认分支只创建裸用户、不创建企业。此类账号 `enterprise_id`/`my_role` 为空，首页按外部协作者视图降级渲染——只剩「与我共享」区、没有「新建多维表格」入口，用户被锁死在空首页，与产品承诺直接冲突。
2. **N5（P1）公式字段创建后存量记录不回填**：新建一个公式/引用字段时，该表**已存在的记录**的新列值从未被物化（值为空、前端永远显示「计算中…」）；只有该行的引用列被再次编辑后才会补算。字段越多、表越老，现象越普遍。
3. **N2（P2）人员字段候选列表为空**：人员编辑器的候选目录唯一数据源是 Base 的**外部协作者**列表；所有者与企业成员不在其中。owner-only 的企业里人员字段永远无法选择任何值（网格与抽屉同源）。

另有一个**工程事故教训**必须随本批一并堵上：本批整改期间，核心服务的集成测试在共享 dev 库上执行了「清空当前库全部表再重放迁移」的复位逻辑（集成测试的恢复路径），把 live stack 正在使用的 `excel_core`/`excel_worker` 数据清空（binlog 证据链完整）。任何后续在本仓库跑后端测试的人都会再踩一次。

## Solution

- **N7**：注册的默认分支补齐产品承诺——自动创建默认企业（名称由用户名派生），用户与企业同事务落库，会话主体携带企业 ID。
- **N5**：公式/引用字段的成功创建、复制、转类型（含转出为公式/引用的更改类型）路径，向现有事件总线入队按表的幂等重算作业，由既有 calc 消费者对全表记录物化新字段的值；大表按批次入队防止单事务过大。
- **N2**：人员目录接口返回「Base 外部协作者 ∪ 企业成员 ∪ 所有者」的并集（按调用者身份裁剪可见范围：外部协作者仅见该 Base 的协作者，不泄露企业全员名单）；前端目录逻辑不变。
- **前置护栏**：核心服务后端测试一律使用独立测试库（由测试框架自建自删），共享 dev 库（live stack 所用）禁止被任何测试触碰——以「库名不带测试后缀即拒绝清库操作」的硬护栏落地。

## User Stories

1. As a 注册用户, I want 注册时不填企业名称也能自动拥有一家企业, so that 我不会落进一个没有「新建」按钮的空首页。
2. As a 注册用户, I want 默认企业有一个合理可改的名称, so that 首页与企业管理处不出现空白或乱码名称。
3. As a 企业所有者, I want 注册完成后立即进入完整首页（星标/最近访问/我创建的/新建入口）, so that 我能马上开始建表。
4. As a 已存在的孤立账号（此前未建企注册的用户）, I want 本批修复后首次登录时获得补建的企业, so that 我不需要重新注册。
5. As a 表格建立者, I want 在含存量记录的表上新建公式字段后, 存量记录的公式列立即出现计算结果, so that 不再出现永远「计算中…」的列。
6. As a 表格建立者, I want 把已有字段转成公式/引用类型后, 存量记录同样立即回填, so that 类型转换不产生半空的列。
7. As a 表格建立者, I want 复制一个公式字段后, 副本字段对存量记录同样回填, so that 复制行为与新建一致。
8. As a 表格建立者, I want 回填过程幂等可重跑, so that 重复触发不会产生重复值或脏状态。
9. As a 大表使用者, I want 回填按批次推进而非单事务一次吞全表, so that 字段创建不会因回填长时间锁表或超时。
10. As a 表格使用者, I want 公式回填完成前单元格仍显示「计算中…」占位而非空白或错误, so that 状态语义清晰（沿用现有渲染契约）。
11. As a 人员字段使用者, I want 候选列表里能看到本企业的所有成员（含所有者自己）, so that owner-only 团队也能正常指派人员。
12. As a 人员字段使用者, I want 候选人显示名称而非 ID 串, so that 选择时认得出人。
13. As a Base 外部协作者, I want 人员候选只包含我所在的协作者范围而不泄露企业全员名单, so that 企业隐私不因人员字段外泄。
14. As a 已被选入人员字段的成员, I want 移除后存量值显示「已删除的选项」式兜底, so that 历史记录不出现 ID 乱码（沿用票 04 建立的兜底语义）。
15. As a 后端开发者, I want 集成测试永远只触碰独立测试库, so that 任何人跑测试都不会再清空共享 dev 库。
16. As a live stack 运维者, I want 测试与运行环境在数据库层面天然隔离, so that 服务重启/测试不再互相踩踏。
17. As a 开发者, I want 清库护栏在违反时硬失败并给出清晰报错, so that 误配置立即暴露而不是静默清库。
18. As a 验收者, I want 三个缺陷的修复都有 E2E 或集成级自动化证明, so that 修复不依赖手工回归。

## Implementation Decisions

- **前置护栏（先行票，硬约束）**：核心服务测试框架统一改为「独立测试库」模式——测试库由测试框架按固定前缀（如 `excel_core_test`）自建/迁移/清理；现行「清空当前库全部表」的复位路径改为仅作用于测试库，并在执行清库前校验库名后缀，非测试库直接硬失败。worker 侧同口径。live stack 所用库名不含测试后缀，天然被护栏保护。
- **N7**：注册的默认分支（企业名称与链接令牌均为空）改为「创建默认企业 + 创建用户」同事务落库，复用既有「用户+企业」组合落库通道；默认企业名称由用户名派生（形如「{username} 的企业」，超出企业名长度上限时截断，过短时以固定文案兜底），企业名无唯一约束不查重；会话主体与注册响应补齐企业 ID 与角色（所有者）。**孤立账号补建**：登录/鉴权读取时发现内部用户无企业则同规则补建（幂等），避免存量账号无人问津。
- **N5**：结构域字段写路径（新建字段/复制字段/更改类型到公式或引用）在自身事务内经事件总线入队 calc 重算作业：载荷含作业 ID、表 ID 与新公式/引用字段 ID 列表，不含触发记录——既有 calc 消费者对无触发记录的作业按表全量记录物化（幂等键去重天然防重跑）。**分批**：作业按记录页切分（批次大小由票定，原则为单作业事务量可控），字段创建事务只入队首批+分批调度由消费者沿用现有重放机制。转出公式/引用（改为其他类型）需同步清理对应物化列（现有删除字段级联已覆盖删除场景，转类型按同口径复用）。
- **N2**：新增人员目录聚合口径——「Base 协作者 ∪ 企业成员 ∪ 所有者」，服务端按调用者身份裁剪：内部用户返回企业全员+协作者并集；外部协作者仅返回该 Base 协作者集合。响应形状与现有协作者列表对齐（user_id/username/display_name），前端目录函数仅改数据源路径不改映射逻辑。企业成员显示名取成员表展示名，缺省回落用户名。
- **兼容红线**：不改既有 RPC 的请求/响应字段（新增能力走新增端点或既有端点的向后兼容扩展）；不改注册/登录限速与会话语义；公式物化值形状与既有「计算中…/#ERROR」渲染契约不变；人员字段存量值的兜底语义沿用票 04。
- **事件命名**：新入队的重算作业沿用现有 calc.job 主题与载荷形状（不新增主题），避免消费者双轨。

## Testing Decisions

- **好测试标准**：只测外部行为——「空企业名注册后 auth/me 有企业 ID、首页数据可取」「建公式字段后存量记录的单记录读取含物化值」「owner-only 企业的人员目录含所有者」「外部协作者目录不含企业全员」。
- **接缝（全部沿用现有体系）**：
  1. Go 表驱动/集成测试（iam 注册与补建、structure 字段路径入队、calc 消费者回填、人员目录聚合与权限裁剪）——**全部跑在独立测试库上**（前置护栏落地后的既有测试基建），prior art：现有 iam 集成测试与 calc 消费用例。
  2. 前端组件级/MSW：人员目录数据源切换后的注入与显示（含空目录降级）；注册响应会话形状变化的消费。
  3. E2E 增补（沿用 m2-fixes spec 的 TC 规则与限速规避策略）：空企业名注册→首页完整；含存量记录的表建公式字段→存量行公式值可见（等回填完成）；owner-only 企业人员候选含所有者。
- **先决顺序**：前置护栏票必须最先落地并通过验证（护栏生效后再允许任何后端测试进集成流水），其余三票并行。

## Out of Scope

- 企业成员管理 UI（邀请/移除/角色页）——人员目录只做读取聚合。
- 公式跨行依赖的增量实时推送（WS 接线属 M3）。
- UpdateCellResponse 的重算结果扩展（维持快修口径，M3 一并评估）。
- 历史 binlog 的数据抢救与回放（如需由运维手工执行）。
- 测试库隔离的全仓改造（本批只落核心服务侧护栏 + 本批用例接入；worker 及其他模块迁移为后续票）。
- 已删除用户的存量人员值清理策略（沿用现有兜底显示）。
