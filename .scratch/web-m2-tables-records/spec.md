# M2 前端：认证/首页/工作台闭环（数据表 · 字段 · 视图 · 记录编辑）

Status: ready-for-agent

## Problem Statement

`web/` 目前只有 M1 工程底座与占位页：登录页、首页、Base 工作台都只渲染标题与试运行声明，没有任何真实业务表单或数据加载。后端三个服务与 93 条 HTTP 契约已就绪（M2 所需的 H-01~H-04、H-21~H-28、H-29~H-54、H-77~H-81、H-91~H-92 均可调用），但用户无法在浏览器里完成任何一件真实工作：

- 新用户无法注册/登录，因此拿不到会话；
- 已有用户无法在首页看到自己的 Base，也无法新建 Base 进入工作台；
- 无法建表、配字段、录数据、切视图——P0 的核心使用闭环完全缺失。

本里程碑交付后，单个用户应能在浏览器内完成「注册 → 登录 → 首页新建/打开 Base → 建表与配字段 → 录入/修改/删除记录 → 用视图筛选/排序/分组查看」的完整旅程，这是后续 M3（实时协作）与 M4（评论/分享/导入导出）的必要地基。

## Solution

在既有 `web/` 工程内补齐三段连续的用户旅程，全部消费 M1 已定型的底座（grid 核心、httpClient、error-catalog、游标 helper、query key 工厂、Zustand stores、ui-kit）：

1. **认证**：注册（三条归属路径：直接建企业 / 企业邀请 / 分享链接）、登录、登出、当前会话查询；会话过期统一引导重登。
2. **首页**：Base 聚合列表（最近访问 / 我创建的 / 与我共享 / 星标）、按名称搜索、新建 Base、卡片更多菜单（重命名 / 复制 / 删除 / 星标）；外部账号不出现新建入口。
3. **Base 工作台**：五段式布局（顶栏 / 表与视图栏 / 网格 / 底栏 + 右侧记录详情抽屉），落地数据表 CRUD、11 种字段类型的渲染器与编辑器及配置面板、视图 CRUD 与全量视图配置（筛选/排序/分组/显隐/冻结/行高/字段宽度）、记录的游标分页查询/新增/编辑/批量/删除/撤销、字段级权限呈现。

不引入新框架或新运行时依赖；所有服务端交互沿用既有 HTTP 信封与错误码目录，所有单元格渲染与键盘行为沿用既有注册表与键位状态机。

## User Stories

### 认证

1. As a 新用户, I want 在注册页填写用户名与密码即直接创建企业并进入首页, so that 我能立即开始建表。
2. As a 被邀请者, I want 从企业邀请链接进入注册页时看到差异化的归属提示文案, so that 我明白自己将加入已有企业而不是新建企业。
3. As a 持分享链接的访客, I want 通过链接注册时被带入该 Base 的可访问范围, so that 我注册后直接到达该表格。
4. As a 注册用户, I want 用户名/密码不符合规则时看到字段级错误（长度、字符集、必须含字母与数字）, so that 我不用猜测失败原因。
5. As a 注册用户, I want 用户名重复时看到「用户名已存在」提示且已填内容不丢失, so that 我只改用户名即可重试。
6. As a 已注册用户, I want 用用户名与密码登录后回到我原本要访问的页面, so that 深链不会因登录而丢失上下文。
7. As a 登录失败用户, I want 看到「用户名或密码错误/已锁定」提示与「遗忘密码将无法使用」的说明, so that 我知道 P0 没有找回密码入口。
8. As a 会话过期用户, I want 看到重登弹窗，登录成功后回到原页面, so that 中断的编辑上下文可恢复。
9. As a 已登录用户, I want 主动登出后回到登录页, so that 共享设备上的会话被清除。
10. As a 任意访客, I want 登录页、注册页、首页固定展示试运行免责声明, so that 我知晓数据留存与备份风险。

### 首页

11. As a 内部用户, I want 首页按「最近访问 / 我创建的 / 与我共享 / 星标」分区展示 Base 卡片, so that 我能快速找到常用表格。
12. As a 用户, I want 按名称搜索 Base, so that 表格多时不必滚动查找。
13. As a 用户, I want 点击「新建多维表格」立即创建并进入工作台, so that 我能零摩擦开始搭建。
14. As a 用户, I want 卡片展示名称、表数、最近修改时间与修改人、星标状态, so that 我能判断该打开哪一个。
15. As a 用户, I want 通过卡片菜单重命名/复制/删除/切换星标, so that 我能管理自己的 Base。
16. As a 用户, I want 删除 Base 前看到「P0 不可恢复」的强提示二次确认, so that 我不会误删。
17. As a 用户, I want 没有共享或没有创建记录时看到克制的空态引导, so that 页面不堆砌无用入口。
18. As a 外部账号, I want 首页不出现任何新建入口, so that 我不会进入无权限的流程。

### 工作台骨架与数据表

19. As a 用户, I want 打开 Base 后看到顶栏（名称/保存状态/在线头像位/分享入口位/更多）、表与视图栏、网格、底栏五段式布局, so that 界面结构与需求一致。
20. As a 用户, I want 通过表标签页切换数据表, so that 同一 Base 的多表可并行使用。
21. As a 可管理, I want 新建/重命名/复制/删除数据表, so that 我能组织业务结构；最后一张表不可删除。
22. As a 用户, I want 有在途写请求时表标签显示「保存中」微状态, so that 我知道改动尚未落库。
23. As a 用户, I want 顶栏「更多」提供重命名/复制/删除/星标（按角色显隐）, so that Base 级操作有统一入口。

### 字段

24. As a 用户, I want 网格表头按字段顺序展示，主字段固定第一列且不可隐藏/删除/拖动, so that 记录始终有可识别的显示值。
25. As a 可管理, I want 点击末列「＋」选择 11 种字段类型并命名即新增字段, so that 我能按业务需要扩展列。
26. As a 可管理, I want 重命名字段、查看悬停显示的字段描述, so that 表头语义清晰。
27. As a 可管理, I want 在字段配置面板调整类型专有参数（数字格式/小数位/千分位/货币、日期格式与是否含时间、人员是否多选、关联目标表与是否多条、公式表达式、选项允许录入新建）, so that 字段行为符合数据要求。
28. As a 可管理, I want 更改字段类型前看到受影响记录数与将清空值数量的预览，确认后才生效, so that 转换风险可控。
29. As a 可管理, I want 删除字段前看到影响面（记录数、依赖公式数、依赖引用数）并二次确认，视图条件被自动移除, so that 不留下失效配置。
30. As a 可管理, I want 复制字段时只复制配置不复制数据, so that 我能快速建相似列。
31. As a 可管理, I want 维护单选/多选选项（增删改、拖拽排序、调色板自动分配颜色、删除已用选项二次确认）, so that 选项字典始终可控。
32. As a 可编辑, I want 当选项开关关闭时录入无匹配选项看到「联系表格管理员添加」提示且不能新建, so that 选项不被随意扩张。
33. As a 用户, I want 拖拽列边界调整字段宽度并持久化到当前视图, so that 每张视图能适配自己的展示需要。
34. As a 可编辑, I want 表头菜单按角色裁剪（字段删除/类型修改仅可管理可见）, so that 越权入口不可见。

### 视图

35. As a 用户, I want 切换视图并在每个表至少保留 1 个默认「表格」视图, so that 数据有稳定的展示入口。
36. As a 可编辑, I want 新建/重命名/复制/删除视图, so that 我能为不同场景建立不同视角。
37. As a 用户, I want 使用最多 5 条 AND 筛选条件，操作符按字段类型给出正确选项, so that 我能精确定位记录。
38. As a 用户, I want 使用最多 3 级排序且空值统一排最后, so that 有序展示符合预期。
39. As a 用户, I want 按单个字段分组（单选/多选/人员/日期按日/周/月）并折叠组, so that 数据能按维度归拢。
40. As a 用户, I want 隐藏任意非主字段、设置冻结列、切换三档行高, so that 展示密度与可读性可控。
41. As a 用户, I want 配置即时保存（全量替换）且工具栏按钮显示已启用条件数徽标, so that 不必手动提交。
42. As a 用户, I want 筛选/排序/分组变更时游标重置并全量重拉, so that 新条件下的数据完整而非拼接旧页。
43. As a 用户, I want 所有字段被隐藏时看到「所有字段均已隐藏」与恢复入口, so that 我不会面对空白网格。

### 记录与网格

44. As a 用户, I want 网格按游标窗口按需加载记录并支持纵向虚拟滚动, so that 大表也能流畅浏览。
45. As a 用户, I want 通过底栏「+ 新增记录」、末行方向下键、首行幽灵行三种入口新增记录, so that 录入路径符合习惯。
46. As a 用户, I want 双击/F2/Enter/直接打字四种通道进入单元格编辑, so that 单击只选中不误触编辑。
47. As a 用户, I want Enter 提交下移、Tab 提交右移、Esc 取消不落盘, so that 键盘录入连贯。
48. As a 用户, I want 11 种字段类型按各自规则渲染（文本省略、数字格式、选项标签与颜色、日期格式、人员头像姓名、附件缩略图、超链接、公式结果含 #ERROR、关联标签、引用值）, so that 每类数据都可读。
49. As a 用户, I want 编辑提交后本地乐观更新并在失败时保留输入, so that 录入不丢内容。
50. As a 用户, I want 版本冲突（4001）时看到「该单元格已被 [B] 修改为 [新值]」与三动作弹窗（采用对方 / 覆盖 / 复制我的内容）, so that 冲突不被静默覆盖。
51. As a 用户, I want 记录或字段已被删除（4002）时看到说明并保留可复制内容, so that 我的输入不会凭空消失。
52. As a 用户, I want 选区复制为 TSV、单值/单行粘贴经批量接口落库，并提示只读列跳过格数与不匹配选项置空格数, so that 表格迁移效率高。
53. As a 用户, I want 勾选一行或多行后批量删除、复制记录（读+建组合，不复制评论与历史）, so that 行级操作完整。
54. As a 用户, I want 删除记录后底栏出现「已删除 n 条 [撤销]」并保留 7 秒, so that 误删可即时挽回。
55. As a 用户, I want Ctrl/Cmd+Z 撤销本次会话内最近一步编辑，刷新后不可用, so that 输入错误可快速回退。
56. As a 用户, I want 视图无排序规则时可拖行手动排序，有排序/分组时禁止并提示「当前为排序视图」, so that 排序语义不被破坏。
57. As a 用户, I want 达到单表 5 万行上限时新增被拒并提示联系管理者, so that 我能理解容量边界。
58. As a 用户, I want 打开记录详情抽屉查看当前视图隐藏字段并编辑全部可编辑字段、上一条/下一条按视图顺序切换, so that 单条记录可集中查看。
59. As a 用户, I want 附件字段在抽屉内集中预览、上传、下载、重命名、删除, so that 文件类字段可用。
60. As a 可填写, I want 网格只显示我创建的记录且只能编辑自己的记录, so that 外部填报范围受控。
61. As a 可查看, I want 所有数据只读且新增/删除入口隐藏, so that 角色边界在 UI 上清晰。
62. As a 用户, I want 顶栏保存状态三态（保存中/已保存/离线提示位）与 5xx 自动重试 3 次后转手动, so that 网络异常有明确反馈。
63. As a 用户, I want 权限中途被降级（3001）时立即转只读并提示「你的权限已变更」, so that 不会继续撞权限墙。

## Implementation Decisions

### 范围与契约口径

- **M2 范围（已确认）**：认证 H-01~H-04（注册/登录/登出/me）、首页 H-21~H-28 的内部版（聚合/搜索/新建/重命名/复制/删除/星标）、数据表 H-29~H-33、字段 H-34~H-40 与 H-92、视图 H-41~H-47、记录 H-48~H-54、附件所需的文件接口 H-77/H-79/H-80/H-81（仅附件用途），以及 H-91（仅用于人员字段候选）。
- **契约基准**：以《接口文档-v0.7》为准（需求文档正文引用的是 v0.6，存在版本漂移；实现按 v0.7 字段与 N1/N2/N3/N4 裁定执行）。
- **认证边界**：仅做 P0 最小会话链路；个人信息、改密、注销冷静期（H-05~H-08）不在本里程碑。
- **首页边界**：只做内部用户的 Base 聚合区；企业邀请待办入口、通知中心、成员管理入口延后（分别属 M4 与管理员能力）。
- **详情抽屉边界**：只做字段区；「评论 / 动态」双标签页延后（M4）。

### 模块与分层

- 业务按 feature 域划分：认证、首页、工作台（表/字段/视图/记录/抽屉）。每个域对外只暴露页面组件与少量 hook；服务端交互统一经 httpClient，不自造第二套请求栈。
- query key 工厂在既有基础上补齐 Base/表/字段/视图/视图配置/单记录域；失效口径沿用技术方案 §7（写成功后按白名单失效，结构变更失效对应结构域）。
- 复用既有 Zustand stores：选择、编辑会话、视图配置草稿、UI 栈。新增的域状态只放瞬时 UI 态，不存服务端数据。
- 例外：为「游标窗口 + 已加载区间」服务，网格数据源需在 feature 内组合既有游标 helper 与既有 LRU 区间缓存，不修改 M1 纯逻辑模块的对外语义。

### 认证

- 会话票据走同源 Cookie（httpClient 已默认携带），不启用 Bearer 备用通道。
- 登录/注册成功后主动拉取 me 作为身份事实源；2001 统一视为「会话失效」，走全局重登弹窗并保留?next= 原路径。
- 登出后清空 Query 缓存与本地编辑态。
- 注册三条路径由 URL 参数区分（企业邀请 / link_token / 无参数），文案差异化；企业名称为可选输入，仅在无邀请与链接时展示。

### 字段与单元格

- 11 种字段类型各自注册渲染器与编辑器；公式、引用只读（不提供编辑器），关联提供目标记录搜索面板，人员候选来自 Base 协作者（H-91/H-63 数据源按可用契约取）；附件编辑器走上传两段式（H-77 → 确认），展示缩略图并支持下载/重命名/删除。
- 单元格值严格按接口文档 8.0.6 编码字典处理：选项存 option_id、多选存 id 数组、日期存毫秒、人员存 user_id、附件存 file_id 列表、超链接存 `{url, display_text}`、公式错误为 `#ERROR:<原因>` 哨兵字符串、空值统一 null。该字典是渲染器与编辑器之间唯一的值契约。
- 数字格式（整数/小数 0-4 位/百分比/货币 ¥$€£、千分位）与日期格式（三种）作为纯格式化逻辑实现并单测；超精度四舍五入、空值与 0 区分。
- 类型转换严格按接口文档 8.5.5 规则：先取预览（受影响数/将清空数），确认后提交；公式/关联/引用三类互转禁止，UI 直接不提供目标类型单选。
- 字段宽度为**视图级** `field_width_map`（N4 裁定，覆盖需求正文「表级统一」的旧表述），范围 40~2000px，未出现的字段用默认宽度（定 160px）。
- 主字段类型仅 text/number/select/formula；主字段固定第一列，不参与隐藏、删除、拖动。

### 视图

- 视图配置全量替换（H-47），面板改动即时提交；提交中合并连续改动，避免逐字符触发请求。
- 配置校验在前端同步执行：筛选 ≤5、排序 ≤3、分组仅 1 个字段；超限的直接拒绝并提示。
- 筛选操作符按字段类型白名单给出（接口文档 8.0.5），不提供无意义的操作符。
- 分组按 N1 裁定降级为「分组字段作第一排序键」：出参平铺、组头**只显示组名与折叠控件，不显示全量记录数**；这是对 AC-VIEW-04 文面的有意偏离，验收以本条为准。
- 行高沿用 M1 三档模型；显隐与冻结只影响展示，不影响数据与导出。
- 视图增删改后重新拉取视图列表并保证至少保留 1 个（删除入口在仅剩 1 个时禁用）。

### 记录与网格

- 查询一律走 H-48（游标 + limit），参数携带 table_id/view_id；筛选/排序/分组/显隐变更时清空已加载区间并重置游标。
- 底栏记录数：契约无总数返回，按 G-3 口径展示「已加载 n 条」，`has_more=true` 时显示「n+」；不虚构总记录数。
- 新增、单元格更新、批量、删除、撤销各走对应契约；批量粘贴统一走 H-52 并读取 `skipped_count` 与逐项失败列表生成提示。
- 乐观更新与冲突管线沿用技术方案 §6.5：本地先应用 + 暂存 version；成功落版本；4001 弹三动作；4002 保留内容可复制、不重建。
- 记录复制 = H-49 读 + H-50 建（N8 裁定），不新增原子接口。
- 删除撤销沿用 H-54 的 7 秒窗口；UI 计时器放既有 UI store，跨页面切换不重置。
- 手动排序仅在视图无排序/分组时可用；拖行结果走 H-52 批量更新排序字段（若视图未暴露排序字段则禁用拖行）。
- 5 万行上限由服务端 5001 兜底，前端在已知达上限时禁用新增并提示。
- 变更广播（WS structure_changed / cell_changed）不在 M2 接线；刷新数据以本地写响应为准。

### 权限呈现

- 新增 `usePermission` 直译需求 §5.1 矩阵（角色 × 内部/外部 → close/hide/readonly/filter-self），所有可操作入口经统一权限门包裹或按字典判断。
- 前端隐藏仅为体验优化：任何 3001/3002 回包都触发全局降级只读并提示，不把前端判断当安全边界。

### 错误与状态

- 复用 error-catalog 13 码文案与恢复策略；写失败保留输入、显示行内错误与重试入口。
- 5xx 自动重试 3 次后转手动重试；网络断开时展示黄色横幅占位（真实离线队列接线属 M3，本里程碑只呈现状态不排队重放）。
- 保存状态三态由在途写请求计数驱动。

### 依赖与构建

- 不新增 npm 依赖；不引入 UI 组件库、日期库、状态机库（日期解析与日历控件自实现，沿用 design token）。
- 构建仍由既有 Vite 配置产出，网关同源托管；首屏并发 chunk 约束不变。

## Testing Decisions

- **好测试的标准**：只断言外部行为——给定输入与状态，断言界面呈现、请求载荷与状态迁移结果；不断言内部函数调用顺序或组件私有结构。所有 mock 只出现在 HTTP 边界（MSW）与纯函数入参。
- **接缝（已确认沿用 M1，不新增）**：
  1. **纯逻辑单测**：值编解码、数字/日期格式化、类型转换预览、筛选操作符白名单、视图配置校验、TSV 解析、删除撤销计时状态机。
  2. **组件测试（RTL + MSW）**：页面与面板在给定 HTTP 响应下的渲染、交互与请求断言；错误码场景统一用既有信封 mock 工厂。
  3. **既有先例**：渲染器注册表测试、游标 helper 测试、错误码目录表驱动测试、网格演示页组件测试。
- **被测模块**：auth 页面与表单校验；home 列表与卡片操作；workspace 的表/字段/视图面板；网格数据加载与空态/错误态；记录编辑提交与 4001 冲突弹窗；删除撤销条；权限矩阵快照；详情抽屉字段区。
- **覆盖底线**：AC-FLD-01~10、AC-REC-01~09（除依赖真实 5 万行滚动的性能项）、AC-VIEW-01~08（AC-VIEW-04 按 N1 裁定调整断言：组头无全量计数）在纯逻辑或组件层可断言；注册/登录/首页/工作台的错误码路径（1001/1002/2001/2002/3001/4001/4002/5001/9001）各有至少一条用例。
- **性能项处理**：AC-VIEW-07（5 万行滚动）与 AC-NFR-01 以既有窗口计算单测 + 手动浏览器抽查代替，真实 E2E 留 M5 收口。
- **完成定义**：`npm run test` 全绿、`npm run build` 成功且首屏 chunk ≤6、手动在浏览器跑通完整旅程（注册 → 登录 → 新建 Base → 建表配字段 → 录改删记录 → 切视图筛选排序分组）。

## Out of Scope

- 评论、通知中心、分享与协作者管理、记录历史与回滚（M4），包括详情抽屉的「评论/动态」标签页。
- 导入与导出（M4）、移动端只读（M5）、Playwright E2E 用例（M5 收口）。
- 个人信息、改密、账号注销与冷静期（H-05~H-08）、企业成员管理/邀请/审计/外链清单等管理员能力。
- 分享链接入口 `/s/{link_token}` 的完整分享体系（M4）；注册时仅消费 URL 上的 link_token 参数。
- P1 全部能力（看板/画册/日历/甘特/表单/仪表盘/通知 WS 推送/二维区域粘贴/拖拽填充/字段级权限等）。

- 新增文档、README 或视觉稿；不引入新依赖。
