# P0 冒烟缺陷修复（网格编辑落库 / 空表契约 / 协作者授权与接口形状）

Status: ready-for-agent

## Problem Statement

前后端集成部署（feature/p0-mvp @ 127.0.0.1:8080）的 P0 冒烟发现两组阻断级缺陷与五组次级缺陷，「注册 → 建 Base → 录数据」核心闭环当前走不通：

- **网格编辑不落库**：单元格编辑提交（合成事件与真实键鼠双路径验证）不发出任何 UpdateCell 请求，服务端 cells 恒为空，而顶栏显示「已保存」——数据丢失且用户被误导。部署 bundle 与当前源码构建 hash 一致，属源码缺陷。
- **空 Base 打开即报错**：真实后端对空表返回 `data:{}`（无 `record_list` 键），前端游标解析按「契约违背」抛错，每个新建 Base 的网格呈现错误横幅，只能盲建一条记录后才恢复。
- **协作授权与接口形状缺口**：「可填写」角色无法授予（后端白名单遗漏）；协作者列表不返回条目 id 且外部条目 username 落成用户 id，导致移除/调角色接口实际不可用；带 view_id 的记录查询条目缺 `cells_map`/`version` 字段（正是编辑链路的头号嫌疑根因）。
- **可靠性**：新协作者加入后约 4 分钟窗口内写请求间歇性 9001（自愈）。
- **错误语义与合规展示**：若干错误码/文案与附录 B 及验收条款不一致；登录页缺明文 HTTP 风险提示；最后一张表删除入口未按 AC 禁用+提示。

## Solution

按「契约先行」修复：后端把 H-48（游标页与条目形状）、H-63（协作者条目）、AddCollaborator（filler 授权）等出参与授权对齐接口文档与需求矩阵承诺的形状；前端保持既有严格游标解析不放宽，将 MSW fixtures 对齐真实信封形状，并修复编辑提交链路使每次提交产生真实 UpdateCell、保存状态如实反映结果；错误码与提示文案按附录 B 与 AC 收口。修复完成后重建部署，以 P0 冒烟集全绿作为收口门槛。

## User Stories

1. As a 新用户, I want 新建的空 Base 打开即显示可录入的网格与新增入口, so that 我能立即开始搭建表格而不是面对报错横幅。
2. As a 录入者, I want 单元格编辑提交后数据真实保存（刷新与服务端读回一致）, so that 我的录入不丢失。
3. As a 录入者, I want 顶栏保存状态如实呈现「保存中/已保存/保存失败」, so that 我不会在数据未落库时误以为已保存。
4. As a Base 管理者, I want 把协作者设为「可填写」, so that 填报场景（AC-PERM-01）可用。
5. As a Base 管理者, I want 移除协作者或调整其角色后立即生效, so that 人员变动可管理且被移除者会话收回。
6. As a 刚被授权的协作者, I want 授权后立即可正常读写, so that 协作不被间歇性 9001 阻断。
7. As a Base 管理者, I want 协作者列表展示真实用户名/显示名并可用于管理操作, so that 我管理的是人而不是一串 ID。
8. As a 表格使用者, I want 带视图筛选的记录查询返回与其他查询一致的完整字段（值、版本）, so that 网格与乐观锁行为可靠。
9. As a 用户, I want 删除最后一张表时入口禁用并有明确提示, so that 我理解为什么删不掉（AC-TBL-02）。
10. As a 排查问题的用户, I want 单记录查询缺参数时返回参数错误而非「已被删除」, so that 错误信息不误导。
11. As a 企业管理员, I want 邀请已属于其他企业的用户时得到明确文案, so that 我知道该邀请未加入企业的人。
12. As a 试运行访客, I want 登录页告知明文 HTTP 传输风险, so that 试运行风险知情（需求 6.5）。
13. As a 登录失败的用户, I want 「用户名或密码错误」与「失败次数过多，请稍后再试」按场景区分, so that 我知道发生了什么（附录 B 2002）。
14. As a 前端开发者, I want MSW fixtures 与真实后端信封形状一致（含空页与缺字段场景）, so that 组件测试能拦住本轮这类契约形状回归。
15. As a 冒烟执行者, I want P0 冒烟集修复后可全绿复跑, so that 发布有客观门槛。

## Implementation Decisions

- **修复顺序**：先修 H-48 条目形状（带/不带 view_id 一致，`cells_map`/`version` 恒在，空值以空 map/null 表达；空页恒返回 `record_list: []` 与 `has_more`/`next_cursor`）——这是编辑链路的头号嫌疑根因；随后诊断网格编辑提交断点（`submitCell`/`trackWrite`/编辑器 onCommit 接线，以实际断点为准，不臆测），验收标准为「编辑提交必发出 UpdateCell 且服务端读回一致」。
- **前端游标解析不放宽**：`extractCursorPage` 对缺列表字段保持抛错（tripwire 设计保留），契约缺口一律修在后端出参。
- **H-63 条目**：增加稳定条目 id（协作者记录主键）；`username`/`display_name` 恒为真实值（外部条目不得落用户 id）；H-65/H-66 以该条目 id 寻址（若现实现以 user_id 寻址则明确文档口径并保持一致）。
- **filler 授权**：AddCollaborator 角色白名单补 `filler`；外部协作者上限仍为 `editor`；链接角色链路（可查看/可填写）不受影响。
- **9001 瞬态**：定位新协作者加入后短窗口内写失败的组件（权限/身份传播或缓存预热路径）；修复后「添加协作者后立即可写」为验收；若判定预热属预期行为，则该窗口内不得返回 9001（应返回可解释的业务码或排队语义）。
- **错误码语义**：H-49 缺 `base_id` → 1001（文档同步标注 base_id 必填）；H-33 删最后一张表 → 专有业务码+文案（非 1001）；邀请已属企业用户 → 独立文案（不复用重名 1002 文案）。
- **UI 提示**：AC-TBL-02 删除入口对最后一张表禁用+提示；登录页补「明文 HTTP 传输风险」提示（需求 6.5）；2002 按失败次数区分两种文案（附录 B）；空单元格占位不出现记录 ID（以字段名或「空」呈现，视觉与可访问名一并核对）。
- **不改**：部署形态、M3~M5 里程碑范围、冒烟已通过用例的行为、`extractCursorPage` 的严格语义。

## Testing Decisions

- **好测试**：只测外部行为——契约测试断言响应形状与状态码，不测内部实现；组件测试断言「提交后服务端可读回」「错误横幅出现/消失」「入口禁用状态」。
- **接缝（全部现有，最高可用缝）**：
  1. 后端网关契约测试（既有契约矩阵风格）：锁 H-48 空页/条目形状、H-63 条目形状、AddCollaborator 角色矩阵、错误码语义。
  2. 前端 MSW 组件接缝：新增「空页缺 record_list（真实后端形状）」与「H-63 真实形状」fixtures；GridArea 编辑提交用例回归（断言 fetch 发出与失败路径文案）。
  3. 部署实例回归：`.scratch/fullflow-test/test-cases.md` 的 P0 冒烟集全绿收口（BUG-4/5 修复后 TC-080-01、TC-090-08 解除阻塞一并执行）。
- **先验**：契约矩阵对齐 C-02/C-07/C-08 的契约测试；`GridArea.write.test.tsx` 编辑提交用例；`check-docs.ps1` 文档围栏保持全绿。
