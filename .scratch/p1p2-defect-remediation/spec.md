# P1/P2 全流程缺陷修复

**Status:** done

## Problem Statement

P1/P2 全流程执行（125/129 条用例）暴露 22 个缺陷，其中 18 个 P1。从用户视角看：

- 导入一个 `.xls` 文件会让整个 worker 退出，随后上传、导入、导出、通知查询全部报「服务暂不可用」，直到人工重启。
- 「复制多维表格」永远失败；「复制数据表」只复制结构，记录全丢。
- 外部协作者（含无企业归属账号）在被分享的 Base 内读记录显示「记录已被删除」、写记录报服务不可用。
- 公式计算出错（如除数为零）时整条写入被拒，用户无法录入中间态数据，也看不到 `#ERROR` 提示。
- 字段类型转换看不到影响预览；删除字段看不到影响面，也无法确认删除；维护单选/多选选项直接报服务错误。
- 实时协作拿不到结构变更、断线重连补不到缺失变更、协作者离线不更新、非法 Base 也能建立连接。
- 「可填写」能评论他人记录、「可查看」能读历史、评论能建到第三级、Base 可管理者删不掉他人评论。
- 伪造的分享链接被引导去注册；带 hash 的静态资源每次回源；越界 Sheet 被静默导入成第 0 个 Sheet；审计缺表删除与导出动作。
- 首页卡片把「最近修改人」显示成内部 user_id；`Ctrl+F` 无搜索；压缩包附件无风险提示；前端完全没有接埋点。

## Solution

按「先数据安全与稳定性，再契约正确性，最后体验项」推进，一次性收口 P1/P2 缺陷：

1. **稳定性**：`.xls` 解析全链路加 panic 兜底与 OLE2 文件头校验，升级/替换易崩库；导入任务失败/中断用独立 context 清理半成品 Base。
2. **结构复制**：补齐 workspace 的记录复制器与 structure 的表记录复制适配器；复制 Base/表同时复制结构、视图与记录，评论与历史不复制。
3. **字段生命周期**：转换预览、删除影响面、选项维护三条写通道修正为契约语义；重名统一 1002；H-35 描述落库。
4. **记录与权限**：外部协作者按 Base 所属企业做租户解析；公式错误落 `#ERROR:<原因>` 哨兵而不是拒绝写入；评论两级、filler 评论范围、viewer 历史、可管理删除评论全部对齐权限矩阵。
5. **实时通道**：握手校验 Base/表存在性与访问权；字段结构变更广播 W-11；断线按 `last_seq` 补发；连接关闭广播 presence 离场。
6. **分享/导入导出/审计**：伪造 token 落失效页；`sheet_index` 越界返回 1001；审计补 `TABLE_DELETED`/`DATA_EXPORT`（含 client_request_id）；H-71 补 `base_name`/`manager`。
7. **静态资源与前端体验**：hash 资产长缓存；首页修改人显示姓名；`Ctrl+F` 视图内搜索；接入 H-94 埋点；压缩包附件风险提示。

## Implementation Decisions

### 1. 稳定性与导入导出（#10、#22、#25）

- **xls 解析**：worker 的 xls 解析入口外层增加 panic recover，任何解析 panic 转为 1001；解析前校验 OLE2/BIFF 魔数；评估升级或替换 `extrame/xls`，并对损坏/加密/非 OLE2 文件补回归夹具。
- **sheet_index 校验**：H-82/H-93 在解析后校验 `0 <= sheet_index < sheet_count`，越界返回 1001，不创建导入任务。
- **导入清理**：任务失败/客户端断连时，任务状态更新与半成品 Base 清理使用独立于请求的 context（如 `context.WithoutCancel` + 超时），保证 `import.finished`/失败事件可靠发出；清理幂等。
- **导入隔离**：保持「导入中 Base 不可访问」，完成/失败后按既定状态机解锁或清理。

### 2. 结构复制（#11、#12）

- `workspace.Service` 的组合根注入记录复制器（当前为 nil）；`DuplicateBase` 逐表复制结构后调用 `DuplicateTableRows`，任一表失败回滚已复制 Base。
- `structure.Service` 的 impact 适配器实现 `TableRecordsDuplicator`，`DuplicateTable` 的结构复制与记录复制在同一业务事务/补偿语义内完成；记录复制保留字段值、版本重置、创建人/时间按新记录语义生成。
- 复制语义保持：结构 + 视图 + 记录复制；评论、历史、审计不复制。

### 3. 字段生命周期（#14、#15、#24、#26、#27）

- **重名错误码**：表/字段/视图/选项重名统一 1002；参数格式/缺失仍 1001。
- **H-40 选项维护**：`UpdateOptions` 的仓储错误映射为契约错误；同名（去空格、忽略大小写）归一而不是失败；基线全量回写必须成功；选项 id 稳定。
- **H-38 转换预览**：`confirm=false/缺省` 时返回 `{affected_count, cleared_count}`，不写库；`confirm=true` 才执行转换；转换失败映射 1001/3001，不返回 9001。
- **H-39 删除影响面**：`confirm=false` 返回 `{impact:{record_count, dependent_formulas, dependent_lookups}}`；`confirm=true` 执行删除并清理视图条件/隐藏/冻结/排序/分组引用；删除后字段不可达 4002。
- **H-35 描述**：网关解码 `description` 并转发 core，字段列表返回；空描述允许。

### 4. 记录、公式与权限（#13、#17、#19）

- **外部协作者租户边界**：所有只读/写记录接口按「数据表所属 Base 的企业」解析租户，而不是按 Principal 的 `enterprise_id`；外部协作者在 Base 授权内获得 `ROW_SCOPE_ALL`（可编辑）/`ROW_SCOPE_OWN`（可填写）；不存在/无权仍按 4002/3001 语义。
- **公式错误哨兵**：写入时公式计算失败不阻断记录/单元格落库，按字段写入 `#ERROR:<原因>`；H-48/H-49/H-55 读取一致；W-14 透传 reason；仅在「保存时校验」阶段（字段不存在/类型不匹配/环）拒绝保存。
- **评论层级**：`ReplyComment` 仅允许父评论为一级评论，对二级回复再回复返回 1001；列表两级结构稳定。
- **评论权限**：filler 仅能评论自己可见/自己创建的记录；viewer 不可评论；作者或 Base 可管理者可删除评论；越权 3001。
- **历史可见性**：viewer 拉取 H-55 返回 3001 或无数据；filler 仅自己可见记录的历史。

### 5. 实时通道（#18）

- **握手**：WS 建连时校验会话、Base/表存在性与访问权；非法请求在升级前拒绝（403/404 语义），不挂死。
- **结构广播**：字段/表/视图结构写成功后发布 `structure_changed`（含 `seq`、`change_type`、`table_id`、`field_id`），房间内其他连接收到 W-11。
- **断线重放**：`replay_request(last_seq)` 从持久事件流补发该 Base/表的增量；补发按 seq 去重、单调、不重不漏；`join.last_seq` 等价支持。
- **presence**：连接关闭/离开房间时向房间广播 `presence.online=false`；重复关闭幂等。
- **会话吊销**：保持已修复的「先发 `session_revoked` 再关闭连接」语义，覆盖 link_closed/perm_changed。

### 6. 分享、外链与审计（#16、#20、#23）

- **H-95 失效 token**：缓存未命中且 `share.CheckAccess` 判定无效时，无论是否登录一律 302 `/err?kind=share-link-unavailable`；只有有效 token 才进入注册/进 Base 分支。
- **H-71 外链清单**：`OpenLink` 填充 `base_name`（Base 名称）与 `manager`（Base 可管理者用户名）；与 H-72 强关使用同一 `base_id` 寻址。
- **审计**：表删除发布 `table.deleted` 并落 `AUDIT_ACTION_TABLE_DELETED`；导出成功发布 `data.export` 并落 `AUDIT_ACTION_DATA_EXPORT`，`detail_map` 含 `client_request_id`；保留 180 天与幂等去重。

### 7. 静态资源与前端体验（#21、#28、#29、#30、#31）

- **静态缓存**：带内容 hash 的 `assets/*` 返回 `Cache-Control: public,max-age=31536000,immutable`；入口文档与无 hash 资源 `no-cache`。
- **首页修改人**：H-21 的 Base 摘要返回可读的修改人显示名（缺失回退用户名），前端不再渲染 user_id。
- **Ctrl+F**：网格键盘 `find` 分支打开视图内搜索条，对已加载数据过滤+高亮；不修改服务端视图配置；Esc 关闭。
- **埋点**：新增前端 tracking 模块，按附录 C 事件名批量上报 H-94；登录成功、Base 创建、单元格提交、首屏 ready（`fe_perf_screen_ready`）等关键事件入队；失败静默丢弃、不重试放大。
- **压缩包提示**：`.zip` 等压缩包附件允许上传，但上传成功后展示「压缩包不解压查杀，请确认来源可信」提示。

### 8. 契约与文档同步

- 明确错误码：1002 重名、1001 参数非法、3001/3002 权限、4001 冲突、4002 已删除、9001 仅基础设施不可用。
- H-35 描述、H-38 预览、H-39 影响面、H-40 选项、H-71 外链字段、H-95 失效分支、H-94 埋点在前端/网关/core/worker 的实现口径与接口文档对齐。
- 涉及租户边界的实现遵循 ADR 0004（外部链接账号租户边界）；行级越权错误码遵循 ADR 0003。

## Testing Decisions

- **好测试的标准**：只断言部署后的外部行为——HTTP 信封与错误码、WS 帧序列/连接状态、通过 API 读回的数据与最终可见性；不直接断言私有函数或数据库内部实现。
- **主验收缝（黑盒）**：`http://127.0.0.1:8080` 的 HTTP/WS 边界 + Playwright。复用 `.scratch/fullflow-test/p1p2-api.mjs` 与 `web/e2e/p1p2.spec.ts`，按 TC 编号验收；修复完成后 P1/P2 缺陷用例必须全绿。
- **包级补洞**：仅对黑盒无法构造的路径使用现有 Go harness：
  - worker importexport：xls panic recover、损坏/越界 Sheet、导入失败清理；
  - core workspace/structure：复制 Base/表、转换预览、删除影响面、选项维护；
  - core records/comment：外部协作者行级范围、公式哨兵、评论层级/权限；
  - web-api realtime：握手拒绝、结构广播、replay、presence；
  - gateway：H-95 三分支、静态缓存、H-71 字段填充、审计动作。
- **既有先例**：gateway pipeline fake、share domain governance、records collaborator_write、worker importexport、realtime hub_join/hub_presence/hub_revocation。
- **测试数据**：沿用 `.scratch/fullflow-test/fixtures`（正常 xlsx/csv/xls、脏数据、20k 行、损坏 xlsx、21MB 文件）；外部账号使用链接注册与无企业账号两条路径。
- **回归门槛**：`p1p2-api.mjs` 与 `p1p2.spec.ts` 全绿；P0 冒烟 `p0-api.mjs` + `web/e2e/p0.spec.ts` 无回归；`contract-test.ps1` 与 `check-docs.ps1` 退出码 0。
- **限速**：注册 10/min、登录 20/min，自动化内置 5003 等待重试。

## Out of Scope

- M3~M5 未交付界面：实时协作 UI、冲突三动作弹窗、离线横幅、评论界面、通知中心、分享弹窗、导入导出向导、移动端专属 UI。
- 性能预算（TC-170-01 首屏、TC-170-02 5 万行滚动）与浏览器矩阵（Firefox/WebKit）。
- 企业注销到期执行（TC-150-06）与 9002 服务端冲突的黑盒构造。
- 与缺陷无关的重构、命名调整、依赖大版本升级（xls 库替换除外）。
- 历史遗留空表/脏数据的批量修复。
