# 视图数据加载模型：服务端游标窗口按需加载 + 断线本地队列重放

网格数据采用「服务端游标（cursor）窗口按需加载 + 前端虚拟滚动」；断线时进入离线只读，未送达编辑本地排队，恢复后经 replay_request 补增量并顺序重传本地队列。

## 背景

记录查询接口 H-48 采用游标分页（cursor + limit，默认 20、上限 100）。产品硬指标要求 5 万行规模下首屏 ≤3 秒、滚动流畅，全量拉取在低带宽与内存约束下不可行。离线规则（PRD D28）：断网时已加载数据可浏览、不产生新编辑，断网前已提交未送达的编辑在本地排队，恢复后自动重传；WS 提供 W-07 replay_request 供重连后按 last_seq 补发。

## 考虑过的替代方案

- **一次性全量拉取 + 前端虚拟滚动**：5 万行 × 100 字段的 payload 与内存占用不可接受，且违反首屏指标。
- **纯分页按钮（上一页/下一页）**：切页打断浏览与复制操作，不是协作表格体验；已被游标分页契约排除。
- **视图切换整体重拉**：筛选/排序/分组变更时重置 cursor 并全量重拉当前视图结果，作为唯一例外保留（数据顺序全局变化，无法增量修补）。

## 决策

前端维护两层状态：滚动窗口（已加载 cursor 区间）与本地待传队列。断线期间只读；重连后先 W-07（携带 last_seq）补增量，再顺序重传本地队列，逐条入口均可感知成功/冲突（冲突走 PRD FR-06-3 三动作弹窗）。

## 后果

- 前端状态机复杂度上升：窗口加载、队列重放、冲突对账须在验收清单中被独立条款覆盖。
- 浏览器端不再持有全量数据：全局搜索无法在前端完成，P0 仅提供当前视图内已加载范围过滤（Ctrl+F），跨表全文搜索列入契约缺口清单（P1）。
