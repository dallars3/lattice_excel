# 自研表格渲染层（虚拟滚动），不引入成熟表格引擎

前端网格采用自研渲染层（虚拟滚动 + 单元格渲染器），不引入 Univer / Luckysheet / Handsontable 等成熟表格引擎；技术栈锁定 React 18 + TypeScript + Vite（写于《前端需求文档 v0.1》技术栈约束，不另设 ADR）。

## 背景

产品硬指标（整体技术方案 v1.3）：单表 5 万行流畅浏览、1 万行首屏 ≤3 秒、50 人同时在线、他人编辑 1 秒内可见。网格需要在单元格级叠加大量实时协作状态：他人选中/编辑描边（WS cursor/selection/editing）、字段级只读（公式/引用）、11 种字段类型的定制渲染与编辑控件、presence 色块、单元格级错误态。

## 考虑过的替代方案

- **Univer / Luckysheet 等在线表格引擎**：功能面向完整电子表格（合并单元格、样式、多 Sheet），包体大、渲染与样式定制需侵入其内部 API；叠加上述单元格级协作状态时改造负担高于自研；且部分引擎的许可/维护节奏与试运行定位不符。
- **Handsontable / AG Grid 等通用表格组件**：以模型驱动为主，极大数据量下的虚拟滚动细节（窗口回收、行高可变、分组行）与 11 种自定编辑器混合后仍需深度定制。

## 决策

自研：虚拟滚动（按需挂载 + 回收）、选择器模型（单元格/区域）、TSV 剪贴板、11 种字段类型的渲染器与编辑控件、分组行。原因是以上协作状态是产品核心体验，渲染层必须完全可控，而非围绕第三方引擎打补丁。

## 后果

- 需要自行实现并调优虚拟滚动与输入延迟，属本项目主要前端风险点，验收清单以 6.1 性能指标直接检验。
- 只有「表格视图」一种网格形态，自研范围可控；P1 看板/画册等视图复用单元格渲染器而非网格引擎，自研决策不被 P1 推翻。
