| 关联文档 | 产品需求文档 v1.3（评审稿） |

## 1. 设计原则

1. 对齐 8.1 硬约束：单机、无域名无备案（高位端口，建议 8080）、零付费/零企业资质外部依赖、前端静态资源全部自托管；传输加密不做（明文 HTTP 为已确认接受的已知风险），本方案不引入任何 TLS 依赖。
2. 边界先行：先按「数据所有权」切逻辑模块并冻结 gRPC 合同，再按单机资源合并部署进程。组内模块进程内直调，跨组只允许 gRPC 与 outbox 事件。
3. 所有写操作服务端二次鉴权（PRD 4.5）；gateway 只做身份识别与限速，不做授权决策；前端隐藏入口不作为安全边界。
4. 异步任务统一走 MySQL 驱动的 outbox/任务表：不引入 Kafka/NATS/Redis 等额外中间件，最大化降低部署与运维面。
5. 为 P1 预留扩展点（表单、自动化、看板、回收站等），刻意不为 P2（开放 API/Webhook/AI）预留实现。

## 2. 总体架构

```
浏览器 / 移动端 H5
   │  HTTP 明文（PRD v1.3 已确认接受）/ WebSocket（/ws）
   ▼
G1 gateway（Gin，唯一公网进程，监听 8080）
   ├─ /          → 前端静态资源（自托管，零第三方 CDN）
   ├─ /api/v1/*  → 按路由桥接到 gRPC（REST ↔ RPC 映射）
   └─ /ws        → 反向代理到 G5 realtime

内部网络（本机 localhost）：gRPC + MySQL outbox 事件

G2 identity  …… iam / share / audit
G3 workspace…… workspace / structure
G4 data      …… records / calc / comment
G6 worker    …… file / importexport / notify / scheduler
G5 realtime  …… WebSocket 长连接（仅经 G1 可达）

共享底座：MySQL 8（utf8mb4，mysqldump 备份）｜本地磁盘（附件池 5GB + 导入临时区）
```

- 网关是唯一公网监听进程，天然满足「高位端口 + 安全组限制来源 IP」的部署要求。
- 网关保持无状态可重启；业务服务崩溃只影响所在分组，不影响整站登录与静态资源。

## 4. 部署分组（单机 6 进程）

| 进程 | 包含模块 | 对外端口 | 说明 |
|---|---|---|---|
| G1 gateway | gateway | 8080（唯一公网） | 无状态；静态产物随镜像发布；可多副本但单机下仅 1 个 |
| G2 identity | iam、share、audit | 仅 localhost | 身份与角色热路径；审计查询量小并入 |
| G3 workspace | workspace、structure | 仅 localhost | 元数据聚合；字段/视图配置热数据 |
| G4 data | records、calc、comment | 仅 localhost | 性能核心；5 万行读写、公式重算、冲突与历史集中优化 |
| G5 realtime | realtime | 仅 localhost（经 G1 /ws 代理） | 内存态允许丢失；重启后客户端对账重拉 |
| G6 worker | file、importexport、notify、scheduler | 仅 localhost（经 G1 桥接） | IO/异步任务；可独立滚动升级 |

规则与理由：

- 组内模块走进程内 interface（Go `internal/` 包），跨组必须走 gRPC + outbox 事件；此规则保证未来任何组可以 1 拆 2 而不动协议。
- 14 个进程在 2C4G 轻量服务器上内存与运维成本过高，6 进程是 demo 阶段「边界清晰度 vs 单机资源」的平衡点；模块边界仍完整保留在 proto 与代码分层中。
- 部署二选一：docker-compose 一键起停（推荐，容器/镜像免费、无外部依赖），或 systemd 二进制直跑。
- 若团队极小，可再合并为 3 进程（G1；G2+G3；G4+G5+G6），proto 与模块边界保持不变。

## 5. 关键横切设计

### 5.1 proto 合同管理

- 单一事实源 `api/` 目录，按 `api/{模块}/v1/` 组织；buf 做 lint 与 breaking change 检测。
- 公共类型：`common/principal.proto`（UserID、EnterpriseID、Internal 标志、LinkContext）、`common/error.proto`（统一错误码语义：权限/冲突/限速/容量/对象不存在）。
- 组内模块也先定义 proto 后实现，避免默认走「共享结构体」的二义性。

### 5.2 鉴权与授权链路

1. gateway 取出 opaque 会话票据 → 调 iam 换 Principal（本地短缓存），注入 gRPC metadata 后转发。
2. 每个业务写路径调 `share.ResolveRole(base, principal, linkCtx)` 得最终角色与「是否内部成员」标志；再由各服务执行行级约束——可填写仅本人创建记录、关联候选与 Lookup 渲染滤掉无可见权目标记录（FR-03-5/6）。
3. 导出强制断言：内部成员且可管理/可编辑，外部协作者无论显式角色一律拒绝（D13 服务端实现）。
4. 结构变更断言可管理；切分享范围/重置链接断言可管理；企业后台动作断言所有者/管理员。
5. 运营者接口：独立运营者凭证 + 白名单开关，全部动作写审计。
6. 终端形态不构成鉴权维度：移动端禁用编辑是前端展示约束（D29/FR-12），服务端对同一接口一律服务端鉴权，不按 UA/设备限权。

### 5.3 实时推送与对账

- 写事务成功后，records 同事务写 outbox 事件，并行以 gRPC 直推 realtime（热路径）；realtime 按房间成员下发。
- 客户端 WS 事件带递增 `seq`；断线重连上报 `last_seq`，realtime 从 records 拉增量补发。保证他人修改 1 秒内可见、断网恢复不丢可观察行为。
- 在线头像/光标/选区/「编辑中」为纯内存状态，不进数据库；服务重启即重置，客户端自动重建加入。

### 5.4 异步任务与 outbox

- 统一 `tasks` 表 + MySQL `FOR UPDATE SKIP LOCKED` 领取，足够支撑 demo 负载；不引入消息队列。
- 任务类型：导入解析、导出文件生成（可选异步）、跨行公式重算、冷静期执行、过期数据清理。
- 权限查询缓存 TTL 必须 < 60 秒，以满足「关闭/收窄链接后外部会话 1 分钟内失效」。

### 5.5 并发、历史与公式

- records 以 `record_version` 乐观锁：客户端提交带所见版本，不匹配触发 FR-06-3 三选冲突流；批量写组内串行化。
- 同行公式在同一写事务内同步求值；关联/Lookup 引发的跨行重算由 calc 任务在数百毫秒内拾取回写并广播（demo 可接受的短暂陈旧，界面可按需显示「重算中」）。
- 历史与事件表 append-only 递增 seq：支撑 90 天历史展示/回滚、实时对账与审计（审计是动作级独立表，不含单元格内容）。

### 5.6 限速与防滥用

- gateway：按 IP 滑窗计数（内存计数 + 定期落库），对注册、登录、记录提交、评论与@ 全局限速。
- iam：登录失败「用户名+IP」联合计数锁定 15 分钟；注册开关即时生效，关闭后仅邀请路径可注册。
- file：上传扩展名+MIME 双校验黑名单；附件池容量集中计量，池满全站禁传。
- 不接入验证码类风控（8.1.4），滥用由运营者人工处置。

### 5.7 多租户与 ID

- 业务对象 ID 用 ULID（全局唯一、无泄量级）；MySQL bigint 自增仅用于 history/events/tasks 等内部追加表。
- 所有 Base 数据继承 enterprise_id，查询一律租户隔离；外部协作者不归属企业，访问权完全由 share 的授权/链接表解析。

### 5.8 存储与备份

- MySQL 8 utf8mb4；每服务逻辑表前缀隔离（单库即可，避免多库运维负担）。
- 单元格存储首选「行存 + 单元格 JSON」以匹配高频整行读写与复制 Base；若 5 万行筛选/排序实测不达标，再评估专用列/EAV，见待确认 T1。
- 备份对齐 8.1.6：运营者脚本 mysqldump + 附件目录 tar 轮转，或轻量服务器快照；不构成用户备份承诺。

## 6. 关键数据流

### F1 单元格编辑（正常/冲突）

客户端提交（带 record_version）→ gateway 限速 → records 经 share 裁决角色 → 行级可见性校验 → 乐观锁比对 → 事务（写值 + 历史 + outbox）→ calc 同行公式同步求值 → realtime 广播 → 跨行依赖走 calc 任务重算再广播 → 前端显示「已保存」。

### F2 导入 .xlsx

gateway 接收上传到本地暂存区 → importexport 建任务并开始解析 → 预览配置（首行字段名、类型识别与改列）→ structure 建表结构 → records 批量写行 → 错误报告落 file → notify 通知发起人 → audit 记导入动作；导入期间新 Base 标记「导入中」，他人不可访问。

### F3 外部链接访问与熔断

gateway 识别 link_token → share 校验范围/角色（「任何人」仅可查看/可填写）→ 未登录引导注册（路径②无企业账号）→ 会话附带 linkCtx → 每次请求懒校验失效时间 → 关闭/收窄链接时 share 打失效标记 + scheduler 兜底 + realtime 推送断会话 → 1 分钟内外部会话全部失效。

### F4 评论与 @ → 站内通知

comment 写成功写 outbox → notify 消费生成站内通知；接收人在线经 realtime 即时红点推送，离线登录后可见；被删除记录的通知标记「原记录已删除」不可跳转。

## 7. 仓库结构（monorepo 建议）

```
.
├─ api/                       # proto 唯一事实源（buf 管理）
│  ├─ common/v1/              # principal、错误码、分页
│  └─ {iam,share,audit,workspace,structure,records,calc,comment,
│      realtime,file,importexport,notify,scheduler}/v1/
├─ cmd/                       # 每进程一个 main
│  ├─ gateway/  identity/  workspace/  data/  realtime/  worker/
├─ internal/
│  ├─ app/                    # 进程组装层（按部署分组注册模块）
│  ├─ service/{...}           # 各逻辑模块实现（组内 interface、对外 gRPC）
│  ├─ domain/{record,field,formula,...}  # 领域模型与纯函数（26 函数库在此）
│  └─ pkg/{authz,ratelimit,outbox,idgen,storage,xlsxio,config,boot}
├─ web/                       # 前端 React/TS + Vite，构建产物进 gateway 镜像
├─ deploy/                    # docker-compose.yml / systemd / 备份脚本 / seed
└─ docs/                      # PRD、本方案、ADR
```

前端约定：表格网格建议自研虚拟滚动渲染（canvas/DOM 混合），避免引入 AGPL/商业授权的表格内核组件（如 SpreadJS 属付费软件，不可用，违背 8.1.3）；社区开源网格必须核验 MIT/Apache 许可。禁止第三方字体、统计、错误上报 SDK。后端第三方库同样锁定宽松许可并自托管（候选：excelize 解析 xlsx、gorilla/websocket、Go 标准库与社区图像缩放库），引入前逐项核验 LICENSE。

## 8. P1 扩展点（只预留、不实现）

- 表单（D15）→ 新增 `form` 模块：提交走 records + 登录/匿名两种身份，独立分享由 share 扩展表单令牌。
- 自动化 → 新增 `automation`：订阅 records/字段事件，动作限于站内通知、更新字段、新增记录。
- 看板/画册/日历/甘特、仪表盘 → structure 视图类型扩展 + records 聚合查询扩展。
- 回收站 → 各持有服务在删除路径预留软删/回收队列位（P0 不启用）。
- 字段级权限、锁定视图 → share/structure 扩展，不改变 Resolve 合同。

## 9. 权衡、风险与待确认

- 权衡：14 逻辑模块 6 进程是「边界清晰可演进」与「单机资源有限」的折中；模块边界与合同先行，进程数随时可调。
- 风险：单机无高可用（8.1 已声明无 SLA）；明文 HTTP 已确认接受；realtime 内存态重启丢失在线信息（客户端自动对账重建）；跨行公式重算存在短暂陈旧；JSON 行存在 5 万行查询排序下的性能需 PoC 验证。
- 待确认（T）：
  - T1 单元格存储模型与 5 万行筛选/分组实测（决定是否转专用列存储）。
  - T2 50 人在线时 WebSocket 连接与广播内存/CPU 基线。
