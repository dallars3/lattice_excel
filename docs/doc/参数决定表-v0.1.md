# 参数决定表（评审工作单）

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 关联文档 | 产品需求文档 v1.3（评审稿） |
| 用途 | 把 PRD 内散落的 `[假设值，TBD]`、`[TBD]`、`[假设]` 及第 9 章 R1–R6 收拢为一份待决清单，逐项拍板后回写 PRD |
| 事实源 | 以 PRD 为唯一正式事实源；本表仅作评审与勾选工作单 |

## 1. 图例与用法

- 决策方式：**直接采纳**（按建议值拍板）／**实测后定**（依赖压测或磁盘确认，联动 R1/R2）／**运营确认**（写成服务器运营手册，不出现在产品代码）／**形式二选一**（开发前定稿即可）／**P1 延后**。
- 同步规则：每确认一项，回到 PRD 对应行把标记改为 `[已确认]`，本表勾选 ✅；避免本表与 PRD 双份漂移。
- 编号：E=体验与行为，C=容量与数据，S=安全与运营，D=产品规则，P1=一期后，F=性能基线。

## 3. 上线前必办清单（阻塞项汇总）

1. S01：确认端口终值（8080）与安全组来源 IP 策略（R4）。
2. C10：确认服务器可用磁盘与 5GB 附件池终值、池满处置（R2）。
3. S02：定稿附件黑名单首版与维护方式（R3）。
4. F01：完成压测（5 万行/50 人/首屏 3 秒），按结果回写 7.3 相关软上限（R1）。
5. S04：写好试运行终止数据处置预案（R5，运营手册层面）。
6. S05：落地「联系运营者」入口与受理时限（R6，产品内文案/公告页）。

其余行数默认采纳建议值，可上线后按反馈随时调整（调整时按第 1 节同步规则回写 PRD）。

## 4. 回写与维护规则

- 本表是评审工作单；确认结果落回 PRD 对应行（把 `[假设值，TBD]` 等标记改为 `[已确认]`），PRD 保持唯一事实源。
- 每次压测或磁盘变化后，刷新 F01/C10 两行的「已确认值」，并同步 PRD 7.3。
- 建议本表随 PRD 一起放入版本管理；PRD 升版（如 v1.4）时标注「参数决定表已清空勾选」以免误读旧结论。
