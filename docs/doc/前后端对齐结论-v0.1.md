## 1. 前端 dist 静态托管（需后端新增）

- **现状**：`excel_web_api` 全目录无 `FileServer / embed / Static` 实现，网关仅承载 `/api/v1` 与 `/ws`；前端将新增单页应用，需要同源静态托管。
- **结论**：后端需新增静态文件托管能力。
- **建议方案**：`go:embed` 承载构建产物 `dist/`；所有非 API 路径回退 `index.html`（history 路由）；API 与 WS 路径保持优先匹配。
- **归属**：后端实现项；前端构建产物先行产出，接口不变。
- **影响文档**：`前端-技术方案-v0.1.md` 第 16 章。

## 2. 对客埋点上报端点（建议后端新增）

- **现状**：现有审计通路 `audit.Append` 为 **EventBus 服务间消费入口**（proto `audit/v1/audit.proto` rpc Append，按 event_id 幂等），不对客户端暴露；HTTP 清单无任何事件上报路由。
- **结论**：前端埋点（需求文档附录 C，约 30 条事件）**当前无上报去处**。
- **建议方案**：新增轻量对客埋点端点（登录后鉴权、批量上报、本地时间与 userId 由服务端兜底）；可复用审计事件模型（动作枚举/幂等 id），但**与操作审计分流**（埋点量级远大于审计）。
- **归属**：后端立项；前端 `lib/tracker` 采集器先行（本地缓冲 30s/10 条，失败静默丢弃），端点就绪后直连，无阻塞。
- **影响文档**：`前端-技术方案-v0.1.md` 第 13 章。

## 3. 通知实时通道（P0 轮询已定，P1 建议 WS 推送）

- **现状**：WS 消息清单 W-01~W-16（接口文档 3.1/3.2）**无 notification 推送事件**；通知数据仅靠 H-73/H-74 拉取。
- **结论**：PRD FR-08-1「在线即时可见」与契约之间缺少推送通道；P0 采用 **30 秒轻轮询 H-74** 兜底（`unread-count` 单字段、服务端零新增负担）。
- **建议**：接口文档 v0.7 修订时新增 `notification` WS 事件（P1），届时轮询可替换为事件驱动。
- **归属**：P0 前端已按轮询落地；P1 后端修订接口文档并实现。
- **影响文档**：需求文档缺口 G-1；`前端-技术方案-v0.1.md` 第 9 章。

## 4. HTTP/1.1 传输约束（前端已适配，h2c 可选）

- **现状**：`excel_web_api` 无 `http2 / h2c` 依赖（负向证据）；试运行环境为 HTTP 明文直连，无 TLS 升级路径。
- **结论**：按 **HTTP/1.1 硬约束**执行：前端首屏并发 chunk 数 ≤6、关键资源合并加载。
- **建议**：如后续网关引入 `golang.org/x/net/http2` 的 h2c 包装，可将 chunk 上限放宽；属可选增强，不阻塞 P0。
- **归属**：前端已适配（第 12 章）；后端可选。
- **影响文档**：`前端-技术方案-v0.1.md` 第 12 章。

## 5. 「未保存微状态」与「导入中」呈现（无需后端改动）

- **现状**：
  - 导入锁机制已完整实现：`base/workspace.go`（`ImportStatus` 字段，`Importing()` 查询）；`internal/share/check_access.go` 对导入中 Base **全员拒绝**（含所有者）；导入完成经 `import.finished` 事件由 `internal/workspace/consumers.go` 调用 `ClearImportStatus` 自动解锁。
- **结论**：
  - ①「数据表标签页未保存修改微状态」（需求 3.2）为**前端本地态**：在途写请求数 > 0 即展示「保存中」，无需任何后端字段——原待确认项撤销，非缺口。
  - ②「导入中」前端呈现分工已自洽：**发起者**在导入向导轮询 H-83 状态；**他人**访问被拒时展示「表格导入中，暂不可访问」提示。无新增缺口。
- **可选项**（非 P0）：若未来要在首页 Base 卡片展示「导入中」徽标，需在 Home/Base 响应暴露 `import_status` 字段——备选增强，另行立项。
- **归属**：无必办事项。
- **影响文档**：`前端-技术方案-v0.1.md` 第 17 章第 5 项。
